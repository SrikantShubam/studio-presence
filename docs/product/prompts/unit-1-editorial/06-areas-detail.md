# Unit 1 — Editorial — Service area page (conditional)

Attach: none required

## ⚠️ Ships only if the content gate is met — and this page carries the higher risk of the two

Locality pages are how Tier 2-3 local search is actually won ("interior designer in Kankarbagh" is
winnable; "interior designer" is not). But they are also the **most likely thing in this entire
template set to earn a Google penalty**, because five pages that differ only by place name is the
textbook doorway-page pattern.

**Gate: no area page ships without a real completed project in that locality and 150+ words written
about that specific area.** If the studio has projects in two localities, ship two pages. Never
generate a locality page for an area they haven't worked in.

Paste `00-identity-system.md` first, then this:

```
Design the SERVICE AREA page for one locality: "Interior Designers in Boring Road, Patna".

NAV — per Global Chrome, white background, not overlaid.

Structure:
- Two-tone heading: "BORING ROAD / PATNA"
- Small uppercase eyebrow: "WHERE WE / WORK"
- An opening paragraph, 150–200 words, genuinely specific to this locality — the kind of housing
  stock there (older 3BHK builder flats, newer apartment towers), typical project sizes, what
  local homeowners usually ask for. This has to be real observation, not a place name dropped into
  boilerplate.
- 2–3 real projects completed in this locality — cards with photo, title, duration, linking to
  their full case studies
- A small map showing the area
- A short "we also work in" row listing neighbouring localities as plain text links
- Gold CTA: "Discuss a project in Boring Road"
- FOOTER — per Global Chrome spec

REQUIRED: at least 2 signature devices.

ANTI-GOALS: same as the home page. Critically — if this page could become the "Kankarbagh" page by
find-and-replacing the locality name, it is a doorway page and must not ship. The opening paragraph
and the projects shown must be specific to this area. Do not design a version that reads as
fill-in-the-blank.
```
