# Unit 1 — Editorial — Careers

Attach: none required

Reference: [BAMO](https://bamo.com/) carries careers in the footer. A firm running five projects a
month is hiring more or less continuously, and design talent checks the studio's own site before
anything else.

Paste `00-identity-system.md` first, then this:

```
Design the CAREERS page.

NAV — per Global Chrome, white background.

AUDIENCE NOTE: this is the one page on the site not addressed to a client. The reader is a designer
or junior architect deciding whether they want to work here. They want to know what the work is
like and whether they'd be any good in it — not a corporate values statement.

STRUCTURE:
- Two-tone heading "WORK / WITH US", small uppercase eyebrow above
- One paragraph on the practice as a place to work — team size, what a typical project looks like,
  what someone would actually be doing
- A studio photograph — people working, not an empty styled interior
- "WHAT WE LOOK FOR" — 3–4 ghost-numbered points, specific rather than generic
- OPEN ROLES as a list. Each row: role title, type (Full-time / Internship), location, and a
  "View details →" link. Design for 3 open roles
- An expanded role detail state, inline or as its own panel: responsibilities, requirements,
  what the first six months look like, how to apply
- An APPLY block: email address, what to send (portfolio PDF, CV), expected response time
- An empty state for when nothing is open: "No open roles right now — send us your portfolio
  anyway, we keep good work on file." With the email address.
- FOOTER per Global Chrome

REQUIRED: at least 2 signature devices.

ANTI-GOALS: same as the home page. Additionally — no perks-and-benefits icon grid (ping-pong,
free snacks), no "we're like a family" copy, no application form with fifteen fields. An email
address and a clear list of what to send beats an applicant-tracking form at this scale.
```
